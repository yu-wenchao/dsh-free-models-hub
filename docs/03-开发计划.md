## 开发流程约定

1. **分支模型**：`main` 受保护；功能分支 → PR → 自查（04 清单）→ 合并。单人开发也保留 PR 留痕。
2. **提交规范**：Conventional Commits（feat/fix/docs/chore/refactor/test），CHANGELOG 由提交归纳。
3. **版本策略**：Semver。DSH 预览期破坏性适配升 MINOR（如 0.1→0.2），修复升 PATCH。
4. **兼容承诺**：每次适配新 DSH 版本在 CHANGELOG 标注"已验证版本号"。
5. **缺陷响应**：市场 issue 区按模板收集（环境/dsh 版本/复现步骤），P0（安装失败/崩溃）24h 内回应。
